# 算法服务主机白名单配置与排障

适用环境：通过 `ssh bdca` 维护的 `brss1-algorithm` 容器。
最后更新：2026-10-16。

## 1. 什么时候查这份文档

后端更换域名、文件存储下载域名或回调域名后，算法出现以下错误：

- `该 MinIO 地址不在允许的主机列表中`：检查 `BVH_MINIO_ALLOWED_HOSTS`。
- `回调地址不在允许的主机列表中`：检查 `BVH_CALLBACK_ALLOWED_HOSTS`。

主机白名单与 URL 格式校验是两件事。如果 HTTP 422 提示 `relative URL without a base`，说明后端传入了相对路径，需要后端提供完整 HTTP/HTTPS 地址，添加白名单不能解决。

## 2. 实际配置位置

生产服务器配置在 `/brss1.0/docker-compose.yml` 的 `services.algorithm.environment`，此次没有写入 `.env`，也没有修改 Python 源码。

2026-10-16 修复后的相关值如下（仅为配置片段，不要用它覆盖整个 Compose 文件）：

```yaml
services:
  algorithm:
    environment:
      BVH_MINIO_ALLOWED_HOSTS: 192.168.10.41,172.30.40.13,minio,work.bdcatek.com,performance.bdcatek.com
      BVH_CALLBACK_ALLOWED_HOSTS: platform,brss1-platform
```

- 下载白名单对应文件 URL 的主机名；回调白名单对应后端回调 URL 的主机名。
- 填主机名或 IP，多个值用逗号分隔，不填协议、端口和路径。
- 两种白名单独立，只修改实际需要的一种。
- 保留校验，不要通过清空白名单来解决问题。当前实现中，空白名单会允许任意主机。
- 当前匹配逻辑也允许所填域名的子域名，因此应配置尽可能具体且可信的域名。
- 本地开发可在自己的 `.env` 配置同名变量；如果 Compose 的 `environment` 显式设置了值，仅修改 `.env` 不会覆盖该值。

相关代码：`src/bvh_processing/config.py`、`src/bvh_processing/services/download.py`、`src/bvh_processing/services/callback.py`。

## 3. 快速排查

先登录：

```bash
ssh bdca
```

检查近期错误及容器实际白名单（只输出这两个变量，避免泄露其他环境变量中的密钥）：

```bash
docker logs --since 30m --tail 2000 brss1-algorithm 2>&1 \
  | grep -E '允许的主机列表|source_host_not_allowed|callback_host_not_allowed|relative URL'

docker inspect brss1-algorithm \
  --format '{{range .Config.Env}}{{println .}}{{end}}' \
  | grep -E '^BVH_(MINIO_ALLOWED_HOSTS|CALLBACK_ALLOWED_HOSTS)='
```

从后端本次请求确认实际 `originalFileUrl` 和 `callbackUrl` 的主机名，再与对应白名单比较。不要仅根据浏览器访问的页面域名推断下载或回调域名，也不要公开包含 Authorization、Cookie 或预签名参数的完整日志。

## 4. 修改与生效

重建算法容器会中断尚未完成的任务，先确认维护时机。以下命令在远程服务器执行；当前 `bdca` 会话已是 root，不需要额外提权。

```bash
cd /brss1.0
backup="/brss1.0/docker-compose.yml.bak-host-allowlist-$(date +%Y%m%d-%H%M%S)"
cp -p /brss1.0/docker-compose.yml "$backup"
printf '备份：%s\n' "$backup"

# 用编辑器修改 algorithm.environment 中对应的白名单，保留其他配置。
vi /brss1.0/docker-compose.yml

# 只验证配置，不输出包含其他服务密钥的完整配置。
docker compose -f /brss1.0/docker-compose.yml config --quiet
```

确认校验成功后执行：

```bash
docker compose -f /brss1.0/docker-compose.yml up -d --no-deps algorithm
```

**只执行 `docker restart` 或 `docker compose restart` 不会应用新的容器环境变量。** 需要通过上面的 `up -d` 重建发生配置变化的算法容器，无需重建镜像，也无需重启其他服务。不要使用 `docker compose down`。

## 5. 修改后验证

先重复第 3 节命令，确认容器实际白名单已更新，再执行：

```bash
docker inspect brss1-algorithm --format 'health={{.State.Health.Status}} restart={{.HostConfig.RestartPolicy.Name}}'

docker exec brss1-algorithm python -c 'import urllib.request; print(urllib.request.urlopen("http://127.0.0.1:9001/health").read().decode())'

docker exec brss1-algorithm python -c 'import torch; print("CUDA:", torch.cuda.is_available())'
```

容器启动后健康状态可能暂为 `starting`，待启动完成再检查。

从可信的失败任务中选择一个文件 URL，使用算法自身下载逻辑验证。将下面的 URL 占位值替换为该任务实际的完整地址；不要把含敏感签名参数的地址提交到仓库。

```bash
docker exec -i brss1-algorithm python - <<'PY'
import asyncio
import httpx
from bvh_processing.config import get_settings
from bvh_processing.services.download import download_bvh

SOURCE_URL = "https://替换为可信文件主机/实际文件.bvh"

async def main():
    async with httpx.AsyncClient(timeout=60, follow_redirects=True) as client:
        resource = await download_bvh(client, SOURCE_URL, get_settings())
        try:
            print("下载成功：", resource.source_filename, resource.size, "bytes")
        finally:
            resource.content.close()

asyncio.run(main())
PY
```

该探测只下载并验证文件，不创建重定向任务，也不向业务后端发送回调。最终仍需从业务页面重新提交一次失败任务，确认处理和回调完整成功。旧的失败任务不会因配置修改自动重试。

若白名单错误消失后出现 DNS、TLS 证书、HTTP 403/404 或连接超时，应按新的错误继续排查，不要关闭证书验证或扩大白名单来绕过。

## 6. 回滚

先检查备份和当前配置的差异，确保回滚不会覆盖备份后其他人的改动。如果只需撤销本次域名调整，优先编辑对应白名单。

确实需要恢复整份备份时，替换下方备份路径，执行：

```bash
cp -p /brss1.0/docker-compose.yml.bak-host-allowlist-实际时间戳 /brss1.0/docker-compose.yml
docker compose -f /brss1.0/docker-compose.yml config --quiet \
  && docker compose -f /brss1.0/docker-compose.yml up -d --no-deps algorithm
```

## 7. 本次故障记录（2026-10-16）

- 原因：后端文件 URL 已使用 `performance.bdcatek.com`，算法下载白名单仍只含旧地址。
- 修复：仅在 `BVH_MINIO_ALLOWED_HOSTS` 追加 `performance.bdcatek.com`，回调白名单不变。
- 生产备份：`/brss1.0/docker-compose.yml.bak-host-allowlist-20261016-211001`。
- 验证：重建后使用真实配置下载此前被拦截的 BVH，成功读取 953,767 字节；健康检查正常，CUDA 可用，`restart=always` 和 GPU 0 配置保留。
- 验证范围：完成文件下载验证，修复当时未重新执行完整重定向任务。
- 持久性：配置已写入服务器 Compose 文件，正常主机重启仍保留；以后部署时不要用旧配置覆盖新增域名。
