# BVH 算法服务外部接入检查

检查时间：2026-10-19。通过 `ssh bdca` 检查运行中的容器和 Nginx 配置。本次没有修改远程配置、重启服务或提交算法任务。

## 结论

算法具备 HTTP 接口，可以供其他网站的后端集成；当前尚未配置直接对外的算法入口。推荐使用 HTTPS 域名反向代理，并由第三方网站后端调用，不直接向公网开放无鉴权的算法端口。

## 现在怎样临时调用

同一个 Docker 网络中的后端可以使用：

- 健康检查：`http://algorithm:9001/health`
- 接口文档：`http://algorithm:9001/docs`
- 接口定义：`http://algorithm:9001/openapi.json`
- 处理：`POST http://algorithm:9001/api/v1/bvh/process`
- 合并：`POST http://algorithm:9001/api/v1/bvh/merge`
- 重定向：`POST http://algorithm:9001/api/v1/bvh/retarget`
- 训练：`POST http://algorithm:9001/api/v1/bvh/train`，当前为 Mock 模式。

其他机器可先用 SSH 隧道联调，不改变生产暴露范围。以下命令须由调用机器执行，并保持终端运行：

```bash
ssh -N -L 127.0.0.1:19001:172.30.40.2:9001 bdca
```

然后在调用机器另一个终端执行：

```bash
curl http://127.0.0.1:19001/health
# 文档：http://127.0.0.1:19001/docs
```

`172.30.40.2` 是本次检查时的容器 IP，重建后可能变化。此隧道命令尚未实际建立验证。它只提供 HTTP 访问通道，不会放开文件下载或回调白名单。

## 正式域名调用方案（建议，尚未部署）

复用现有入口时，为算法增加独立前缀 `/algorithm/`，避免与业务后端 `/api/` 冲突。建议调用地址：

- `https://performance.bdcatek.com/algorithm/health`
- `https://performance.bdcatek.com/algorithm/api/v1/bvh/retarget`

这两个地址是拟定接入地址，目前未配置，不能直接使用。

在与算法同一 Docker 网络的 Nginx 中增加如下配置；还需要确认外层域名网关保留并转发 `/algorithm/`：

```nginx
# 配置草案：部署前必须加鉴权与限流，并验证网络和域名证书。
location /algorithm/ {
    proxy_pass http://algorithm:9001/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 10s;
    proxy_read_timeout 120s;
}
```

`proxy_pass` 末尾的 `/` 会去掉 `/algorithm/`，使上游收到原有 `/api/v1/bvh/retarget` 路径。此配置不是完整的生产安全方案。健康检查和接口调用不依赖 Swagger；若同时开放 `/algorithm/docs`，需单独处理文档默认请求根路径 `/openapi.json` 的前缀问题。

也可以使用独立子域名，例如 `bvh-api.你自己的域名`，让根路径转发到 `algorithm:9001`。域名需要正确的 DNS、有效 HTTPS 证书，以及公网到该 Nginx 的连通路径；只增加 DNS 解析不会让 Docker 内部服务自动对外可用。

## 通过 IP 调用（备选，尚未部署）

如果仅在局域网中使用，可在 Compose 的 `algorithm` 下增加端口发布，例如绑定局域网 IP：

```yaml
# 配置草案：需事先确认端口空闲并限制来源。
ports:
  - "192.168.10.41:19001:9001"
```

配置生效后，局域网后端的地址才是 `http://192.168.10.41:19001/api/v1/bvh/retarget`。需要重建算法容器，单纯 restart 不会应用端口映射；重建会中断任务。公网调用还需要 NAT/防火墙或内网穿透配置。`192.168.10.41` 是私有 IP，公网网站无法直接访问。HTTPS 页面直接请求此 HTTP 地址还会遇到混合内容限制。

## 接入方必须满足的条件

### 1. 放行文件下载和结果回调域名

当前容器实际配置：

```text
BVH_MINIO_ALLOWED_HOSTS=192.168.10.41,172.30.40.13,minio,work.bdcatek.com,performance.bdcatek.com
BVH_CALLBACK_ALLOWED_HOSTS=platform,brss1-platform
```

文件域名控制算法从哪里下载 BVH/NPZ；回调域名控制算法将结果发到哪里。它们不是允许哪些网站发请求的跨域配置，也不提供请求鉴权。

第三方的文件主机和回调主机需分别添加到对应白名单，并保证算法容器能够解析、连接、验证其 TLS 证书。保留原值，按具体可信域名添加，不能清空白名单。修改 Compose 环境变量需要重建算法容器。

### 2. 按异步回调方式接收结果

处理、合并、重定向接口先返回任务接收结果，不直接返回最终文件。调用方应先提供回调接口，接收 `multipart/form-data`；重定向结果包含 NPZ 和元数据 JSON 文件。以运行中的 `/openapi.json` 和回调实现为接口合同。

重定向调用示例（正式入口、鉴权和白名单配置完成后才可使用）：

```bash
curl 'https://performance.bdcatek.com/algorithm/api/v1/bvh/retarget' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <网关签发的接入凭证>' \
  --data '{
    "actionId": "external-demo-001",
    "originalFileUrl": "https://可信文件域名/demo.bvh",
    "robotType": 1,
    "callbackUrl": "https://第三方后端域名/bvh/callback"
  }'
```

上述 Authorization 是建议由网关新增的认证机制，当前算法本身不会验证它；仅添加这个请求头不会自动获得安全保护。

接收成功的示意响应：`{"success":true,"taskId":"生成的任务ID","message":"重定向任务已接收"}`。这只表示任务入站成功，不代表算法执行成功。

### 3. 优先后端调用

推荐调用链：第三方浏览器 → 第三方后端 → HTTPS 算法网关 → 算法服务。结果由算法服务回调第三方后端。

这样不用让浏览器直连算法域名，也不用在前端保存接入凭证。若必须浏览器直接跨域调用，还需要明确配置 CORS 来源、OPTIONS、方法和请求头；HTTPS 页面需要 HTTPS 接口。CORS 只管理浏览器访问，不是安全鉴权。

### 4. 增加访问控制和资源限制

对外开放前增加鉴权、限流、任务并发限制和超时管理。当前是共享生产算法服务，外部任务会使用同一计算资源。建议接入网关限定业务接口，避免默认公开开发接口和全部文档。
