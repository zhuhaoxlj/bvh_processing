| 证据 | 结果 |
| --- | --- |
| 容器GPU分配 | DeviceRequests=null，Devices=null |
| 容器内PyTorch | cuda_available=False，device_count=0 |

| 合并实现 | 逐个生成过渡，并重复转换累计合并片段 |

## F 配置与修复方向
前端合并请求超时为300000毫秒。
后端合并等待超时也是300000毫秒。
Nginx代理读取超时为3600秒，不是本次五分钟限制来源。

建议先让算法容器获得GPU，再验证CUDA可用性。
随后用受控任务测量59个过渡的实际耗时。
长期应改为提交任务后返回任务编号，由前端查询进度。
应避免重复提交，并合理处理迟到的成功回调。
单纯提高五分钟限制不能解决CPU计算和任务积压。
