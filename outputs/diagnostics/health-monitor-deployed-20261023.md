## A 三个接口各做什么
| 接口 | 用途 | 异常时行为 |
| --- | --- | --- |
| GET /health | 保持原 HTTP 存活检查 | 仍只返回 status=ok |
| GET /health/details | 读取 GPU 和运行指标缓存 | HTTP 200，内容显示异常 |
| GET /health/ready | 判断本地 GPU 算法是否就绪 | 未就绪返回 HTTP 503 |
原有 Docker 存活检查无需修改。
探测异常不会自动重启容器，避免中断动作任务。
没有配置外部告警通知；监控系统可采集就绪接口。

## B 定时检测如何工作
启动后立即安排第一次探测。
每轮完成后等待 60 秒，再启动下一轮。
独立子进程执行 32×32 CUDA 矩阵运算。
探测会同步 GPU，并校验运算结果。
每轮最多 45 秒，超时后终止并回收子进程。

HTTP 请求只读取缓存，不执行 CUDA 或加载模型。
检测记录时间、耗时、连续失败数和最后成功时间。
长时间未更新的缓存会标记 stale，表示检测已过期。
正在使用 CPU 的已加载模型也会导致未就绪。
GPU 恢复后，已缓存的 CPU 模型不会自动迁移。
该情况需要在维护窗口重启算法服务。

## C 返回哪些指标
| 类别 | 内容 |
| --- | --- |
| GPU | 实际计算是否通过、设备名称、CUDA 与 torch 版本 |
| GPU 显存 | 整卡空闲和总显存，不是模型独占显存 |
| 检测历史 | 检测时间、结果年龄、次数、连续失败数、最后成功时间 |
| 模型 | MDM 动作模型是否已加载、缓存引擎所用设备 |
| 服务 | 进程运行时长、进程驻留内存 |
| CPU | 可见逻辑 CPU 数、主机 1/5/15 分钟负载 |
| 容器 | cgroup v2 当前内存与内存上限 |
| 临时盘 | /tmp 所在文件系统的总量和空闲量 |
资源指标暂不设告警阈值，仅提供观测值。
检测对象是本地算法 GPU，不是云训练服务或业务回调。

## E 配置和运维
| 环境变量 | 默认值 |
| --- | --- |
| BVH_HEALTH_GPU_ENABLED | true |
| BVH_HEALTH_GPU_REQUIRED | true |
| BVH_HEALTH_GPU_INTERVAL_SECONDS | 60 |
| BVH_HEALTH_GPU_TIMEOUT_SECONDS | 45 |
纯 CPU 开发环境可把 GPU_REQUIRED 设为 false。
关闭探测却仍要求 GPU 时，就绪接口保持 503。
修改 Compose 环境变量后必须重建容器。
启动首轮检测完成前，503 是正常初始化状态。
